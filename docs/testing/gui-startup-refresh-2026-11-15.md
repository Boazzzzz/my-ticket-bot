# GUI 啟動與遠大重整修正：2026-11-15

## 問題與已確認原因

使用者回報網頁快速重整時 crash，以及按 GUI 執行按鈕沒有反應。
前次實站已量測到 Chrome 啟動等待 304.4～307.6 秒；日誌指出 Selenium
Manager 版本查詢逾時後才使用快取。原 GUI 沒有啟動／失敗提示，也允許等待
期間重複啟動。詳見 [前次紀錄](gui-launch-2026-11-14.md)。

本次另外確認遠大的待開賣庫存檢查可能每個主迴圈（約 50 毫秒）再次 fetch，
並由非同步回呼直接重整，沒有遵守 GUI 的關閉自動刷新選項或刷新間隔。
部分頁面刷新路徑也沒有最低間隔。主迴圈缺少遠大換頁暫時性例外的處理。

沒有取得使用者當時 Chrome crash 的原始堆疊，因此本輪不能證明所有實機
崩潰皆由上述程式路徑造成，也不宣稱已修復所有 Chrome 原生崩潰。

## 修正

- Selenium Manager 單次網路請求預設等待 10 秒，保留明確設定的
  `SE_TIMEOUT`。這不是整個瀏覽器啟動的總時限，也沒有停用相容驅動更新。
  此環境變數依據 [Selenium 官方設定文件](https://www.selenium.dev/documentation/selenium_manager/)。
- Manager 成功後直接回傳，不再因專案內缺少舊驅動而執行另一個下載器；
  Manager 失敗時才使用既有本機驅動。兩者失敗時傳遞錯誤。
- GUI 立即顯示啟動中，等待瀏覽器就緒前停用執行按鈕；提供已啟動、停止、
  失敗與本機日誌路徑。子程序匯入套件失敗、非零退出、就緒前正常退出，
  都會顯示失敗；較舊程序退出不會解除新啟動的按鈕鎖定。
- 工作執行緒透過 queue 回報，Tk 主執行緒更新新增的 GUI 狀態。GUI 關閉後
  監控工作仍可讀取子程序輸出，避免關閉 pipe 使機器人收到 BrokenPipe。
- 啟動日誌以私人暫存檔儲存、遮蔽已知帳密／憑證與設定字典，保留約 5 MiB
  近期輸出。正式搶票例外與瀏覽器失聯可回報 GUI，不再只有終端訊息。
- 遠大活動頁、票區頁及待開賣檢查共用刷新節流，每個瀏覽器至少間隔 1 秒；
  設定較長間隔時使用較長值，刷新失敗也不會立即重試。
- 庫存查詢每份文件只發送一次，最多等待回應 5 秒；pending 結果交回 Python
  的同一節流路徑刷新。關閉自動刷新時不發出這項查詢。
- 不再將 Selenium script timeout 全域改成 0.1 秒。遠大主迴圈遇到換頁時的
  stale element、timeout、document unloaded 等暫時性錯誤，有限次重試；
  真正 session crash 與持續例外仍停止並回報，沒有自動重下訂單。

既有設定格式保持相同，使用者原有 `settings.json` 不列入提交。
Selenium 的 Chrome 啟動修正共用於各平台；自動重整及換頁重試只調整遠大。
其他引擎與既有打包程式可回報程序已啟動，不推定瀏覽器已就緒。

## 驗證

- 完整測試：73 項既有遠大測試與 29 項新增測試，102 項全部通過（50.354 秒）。
  涵蓋真實子程序匯入失敗、
  啟動後 crash、正常退出、憑證遮蔽、GUI 重複點擊／失敗／舊程序事件、
  Manager 成功與失敗回退、刷新間隔、查詢關閉、換頁例外有限次重試。
- 本機 Chrome DOM 測試覆蓋 inventory ready／pending／網路錯誤，確認每份
  文件只 fetch 一次、JavaScript 不自行刷新、不改 script timeout。
  30 次密集刷新要求會受節流，瀏覽器仍可讀取頁面。
- 真實 Tk GUI 測試從預設空白帳密設定開啟，實際呼叫執行按鈕兩次；子程序
  使用正式驅動啟動函式及本機 data URL。透過本機延遲代理模擬版本服務不回應，
  使用隔離的空 metadata 與相容快取驅動，沒有造訪任何售票網站。
  Chrome 啟動量測 11.8 秒，整段 GUI 測試 14.14 秒；啟動中顯示提示並鎖定按鈕，
  觀察到就緒，再於測試結束時顯示停止及恢復按鈕。
- 通過 Python 編譯及 Git whitespace 檢查。既有 util 正規表示式的 Python
  SyntaxWarning 未在本次範圍內修改。

本機原始證據保留於忽略的 `.tools/gui-startup-fix/`、
`.tools/startup-refresh-all-final.log`。測試使用隔離設定，沒有改寫使用者設定、
登入售票帳號、接受條款、解驗證碼、建立訂單或付款。

本輪未重新實站驗證購票，也未重現作業系統層的 Chrome 原生 crash。
若仍重現，新增的本機啟動／執行日誌可用來分辨是網站換頁例外、驅動失聯，
或 Chrome 本身崩潰。更新後需關閉舊 GUI，重新開啟專案 `.venv` 的 `settings.py`。
