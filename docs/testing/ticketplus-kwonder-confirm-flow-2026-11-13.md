# K-WONDER 自動前進至付款結帳：2026-11-13

## 問題與修正

使用者修復選票頁下一步後，回報同場仍無法自動到付款結帳。
只讀檢查使用者的同一個 Selenium 視窗，確認停在 13:00 加場的 `/confirmSeat/`：
下一步可見且可用、沒有條款 checkbox 或表單錯誤。

原本 `ticketplus_confirm()` 只呼叫條款勾選函式，沒有按下一步的程式。
因此確認座位與填寫資料兩階段都缺少自動前進，並非只需開啟掛機模式。

已補上正式程式：掛機模式啟用時，`/confirmSeat/` 按下一步進入資料頁，
`/confirm/` 確認必要條款已勾選、下一步可用且沒有可見欄位驗證錯誤後前進。
主迴圈傳入共用狀態，同頁送出十秒內不重複點擊；切換階段後可立即處理下一頁。
`/checkout/` 不在自動前進範圍，不選付款方式、不按「前往付款」。

## 行為範圍

- 只處理 `https://ticketplus.com.tw/confirmSeat/活動/場次` 與 `/confirm/活動/場次`。
- 只點可見、可用、文字完全為「下一步」的唯一 `button.nextBtn`。
- 保留原有手動模式的條款勾選，不會在手動模式自動按下一步。
- 真正開啟的彈窗、驗證碼、條款未勾選、按鈕停用、可見的必填／格式錯誤都會等待。
- 保留上一輪對已隱藏 Vuetify 登入面板的修正，隱藏的登入欄位也不會當作資料驗證失敗。
- 沒有新增自動填寫實名制或其他缺漏個資的行為。
- 使用者設定、帳密與其他售票平台不包含在修改中。

手動模式、必填資料與 Email 格式、Vuetify 欄位錯誤、隱藏登入欄位、彈窗、驗證碼、
重複按鈕、路由及來源限制、同頁重複提交、切換階段，以及正式主迴圈停在結帳頁。

完整 73 項回歸測試通過，另完成 Python 編譯與 Git whitespace 檢查。
使用修正前程式執行新增的確認座位案例，下一步未點擊，斷言失敗；
